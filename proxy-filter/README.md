# proxy-filter — v2 architecture

A second filtering implementation that lives alongside the existing
NextDNS-based code in this repo. **Nothing in `backend/`, `admin/`, or
`block-page/` was changed except a single `app.use(...)` line that mounts
this module's router under `/api/proxy-filter/`.**

## What it does differently

The original architecture forces browsers to use a NextDNS profile via DoH.
Two gaps:
- IP-literal traffic (e.g. `https://1.1.1.1`) skips DNS entirely.
- Apps that don't honor browser DoH policy keep working.

This module replaces DNS-only filtering with a **transparent SSL-inspecting
HTTP proxy**. The .mobileconfig:
1. Installs a self-signed CA root on the device.
2. Sets a global system HTTP/HTTPS proxy pointed at our Squid container.
3. Locks the System Settings panes that would let the user remove either.

Squid then sees every URL, decrypts inspected HTTPS using the trusted CA,
and applies destination-domain ACLs. IP-literal traffic still goes through
the proxy because the OS-level proxy setting captures all TCP. The browser
DoH policy from v1 stays in the profile as belt-and-suspenders.

## Layout

```
proxy-filter/
├── server/
│   ├── docker compose.yml          # Squid container + volumes
│   ├── squid.conf                  # SSL bump + auth + ACLs
│   ├── ssl/
│   │   └── generate-ca.sh          # Creates ca.crt / ca.key
│   ├── blocklists/
│   │   └── adult.txt               # One domain per line
│   ├── allowlists/                 # Per-user <user_id>.txt files
│   │   └── global.txt              # Shared allowlist (always allowed)
│   ├── passwd                      # Auto-generated by admin API; gitignored
│   └── block-page.html             # Shown when Squid blocks a request
├── profile-generator/

├── admin/

│   ├── squidOps.js                 # passwd file + allowlist + reload helpers
│   └── router.js                   # Express router mounted at /api/proxy-filter

├── .gitignore

```

## Prerequisites

- **Docker Desktop** (or any Docker daemon with Compose v2). On macOS:
  ```bash
  brew install --cask docker
  open -a Docker     # finish setup + start the daemon
  ```
  Note: the modern command is `docker compose` (space). The older
  `docker-compose` (hyphen) standalone binary is deprecated and not
  installed by default — don't try to use it.
- Node.js 22+ (the parent backend uses it)
- OpenSSL (for `generate-ca.sh`)
- A host with a stable IP/hostname reachable from every device that should
  be filtered. Devices outside that network won't be protected.

## Setup

```bash
# 1. Generate the proxy CA
cd proxy-filter/server/ssl
./generate-ca.sh
cd ..

# 2. Configure environment
cp ../.env.example ../.env
# Edit ../.env — at minimum set PROXY_HOST to the LAN IP / public hostname
# of the machine that will run the Squid container.

# 3. Start Squid
docker compose up -d
docker compose logs -f squid     # check it's healthy

# 4. The parent backend (../backend) auto-mounts /api/proxy-filter when you
#    restart it. Sanity check:
curl http://localhost:4000/api/health
```

### Test the proxy manually before installing any profile

Before trusting the .mobileconfig on a real device, verify Squid works:

```bash
# Create a test proxy user via the admin API
curl -X POST http://localhost:4000/api/proxy-filter/users \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"test","display_name":"Test","proxy_username":"test"}'

# Read back its credentials
curl http://localhost:4000/api/proxy-filter/users/test/credentials \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Try fetching through the proxy with those creds + the CA cert
curl -x http://test:THE_PROXY_PASSWORD@localhost:3128 \
  --cacert proxy-filter/server/ssl/ca.crt \
  https://example.com -I
```

You should see a 200. If you see TLS errors, the CA isn't being trusted —
double-check `--cacert` points at the cert generated by `generate-ca.sh`.

### Install on a Mac

```bash
# Download the .mobileconfig from the admin API
curl -o test.mobileconfig \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  http://localhost:4000/api/proxy-filter/users/test/profile

# Open it on the target Mac:
open test.mobileconfig
# System Settings → Privacy & Security → Profiles → install
```

After install: in any browser, visit a domain on the blocklist
(e.g. `example-blocked-domain.test`). Squid should redirect to the block
page URL.

## Adding users via the admin API

```
POST   /api/proxy-filter/users               { user_id, display_name, proxy_username? }
DELETE /api/proxy-filter/users/:user_id
GET    /api/proxy-filter/users
GET    /api/proxy-filter/users/:user_id/credentials
GET    /api/proxy-filter/users/:user_id/profile        # .mobileconfig download
```

When you POST a user, the router:
1. Generates a random proxy password and removal password.
2. Writes a bcrypt-hashed entry to `server/passwd` for Squid auth.
3. Stores the plaintext passwords in `proxy_users` (needed to regenerate
   the same .mobileconfig later — same usability tradeoff as the v1 module).
4. Calls `docker exec proxy-filter-squid squid -k reconfigure`.

## The four spec endpoints

```
POST   /api/proxy-filter/requests            (public — block-page submits here)
GET    /api/proxy-filter/requests            (admin — ?status= filter)
PATCH  /api/proxy-filter/requests/:id        (admin — { status: approved|denied })
GET    /api/proxy-filter/users/:user_id/profile  (admin — .mobileconfig)
```

On `PATCH ... approved`, the router:
1. Appends the domain to `server/allowlists/<user_id>.txt`.
2. Runs `squid -k reconfigure` so the new allowlist takes effect.

## Updating the blocklist

```bash
# Replace the file with your real blocklist (one domain per line):
curl -o proxy-filter/server/blocklists/adult.txt \
  https://dsi.ut-capitole.fr/blacklists/download/adult.tar.gz   # then extract domains
docker exec proxy-filter-squid squid -k reconfigure
```

## Hosting

For real use you need:
- A box with a stable, internet-reachable address running the Squid
  container.
- The parent backend reachable from every device's browser (block page
  posts there).
- The block page hosted on plain HTTP — see "block page in HTTP" below.

The admin dashboard can stay wherever — it just talks to the backend.

## Block page in HTTP (intentional)

The block page must be served over **HTTP**, not HTTPS. When Squid
deny_info redirects to `https://...`, the device's browser tries to
reach the block page through Squid (since the proxy is global), Squid
sees a denied destination, and you get an infinite redirect / TLS error
loop. Plain HTTP avoids the inspection round-trip.

If you want HTTPS for the block page, run it on a domain that's
explicitly allowlisted in `allowlists/global.txt`.

## Limitations / known issues

- **Per-user allowlists need extra wiring.** `squid.conf` defines a single
  shared allowlist. To make each `<user_id>.txt` only apply to that user
  you must add `acl user_X proxy_auth X` + `acl X_allow dstdomain "..."` +
  `http_access allow user_X X_allow` blocks per user, then reconfigure.
  The router writes the per-user files but doesn't yet edit squid.conf.
- **Bcrypt for Squid passwd**: `basic_ncsa_auth` supports bcrypt only when
  the Squid build was compiled with that helper option. The
  `ubuntu/squid` image is, in our testing — but if your image refuses
  bcrypt hashes, swap `bcrypt.hashSync` in `squidOps.js` for an apr1/MD5
  helper (`htpasswd -nbm`) or run `htpasswd -B` directly.
- **Removal password storage**: stored plaintext for the same reason as
  v1 — the .mobileconfig must keep emitting the same password on re-
  download, and we'd lose that ability with a one-way hash. Protect the DB.
- **HTTP/3 + QUIC** bypasses HTTP proxies. Squid currently ACLs them out
  by default; double-check by visiting `https://www.google.com` and
  searching — if you see "uses QUIC" in DevTools the connection isn't
  going through Squid. Disable QUIC at the browser policy level if
  needed.
- **Non-Apple devices** (Windows, Android, Linux) need their own profile
  installer. The .mobileconfig only works on macOS/iOS.
